Dozer Sandbox

Fast, suspendable Linux sandboxes for coding agents on your Mac.

brew trust --tap dozer-sandbox/tap
brew install dozer-sandbox/tap/doz
doz ui
InstallRead the timeline

Each sandbox is a small Linux virtual machine with your project folder inside it. It starts in about a third of a second, pauses in a millisecond, and hibernates to disk to give its memory back, then wakes with every program still running where it was. Run a coding agent (Claude Code, Codex or pi) with its permission prompts off: the VM is the boundary, the network goes through a policy you can read, and your keys never enter the sandbox.

Why Dozer

  • The VM is the boundaryEach sandbox is its own Linux VM on Apple's Virtualization framework. Root inside it is still only root inside a virtual machine.
  • Keys never enter the sandboxThe proxy swaps credentials in. The sandbox only ever sees a placeholder.
  • A policy you can readThe network is proxied by default, with no network card in the VM. Every connection is judged by permissions you can read and change with doz net permissions.
  • Your project at /workspaceA folder on your Mac, shared into the sandbox. .dozignore and .dozreadonly keep files out of reach or read-only.
  • Sleeps like a laptopPause, hibernate and wake, with programs, sessions and terminal screens as they were.
  • A dashboarddoz ui opens it, it can be installed as an app, and doz serve shows it to your other devices on the network.

Also: restore points and templates (APFS clones), browser sign-ins and open/clipboard bridges back to the Mac, and GitHub as you (read-only by default). For agents: Claude Code, Codex and pi.

The numbers

Start (image prepared)about 0.3 to 0.4 s to a running Linux
Pause / resumeabout 1 ms; attached terminals freeze and continue
Hibernate (sleep to disk)about 0.35 s; its memory goes back to the Mac
Wakeabout 0.3 s, with its programs, sessions and terminal screens as they were
After a crashsleeping sandboxes are restored with their sessions; nothing is lost silently

Measured on an M3 (Alpine guest, 512 MiB to 1 GiB).

Three things worth using it for

A risky change

A dependency upgrade, a big refactor, a migration: let a sandboxed agent work on your project folder with a restore point to fall back to. The changes land in your folder as they are made, so you review them with git diff.

Jail an untrusted agent

Run a new agent CLI or an unfamiliar model in a sandbox that shares none of your folders, holds none of your logins, has the clipboard, browser and file bridges off, and reaches the internet only where you allow it.

A project that holds secrets

Keep .env files, credentials or customer data out of the agent's reach with .dozignore, and make folders read-only with .dozreadonly, without moving anything. These rules guard against accidents; they are not a security boundary.

Install

# once per Mac: Homebrew loads a third-party tap only once trusted
brew trust --tap dozer-sandbox/tap
brew install dozer-sandbox/tap/doz
# opens the dashboard; a new install starts on its setup wizard
doz ui

The setup wizard checks this Mac, chooses how your agent signs in, and prepares an image. Then New sandbox makes one.

Prefer the terminal?

doz onboard         # once: checks this Mac and your agent's account, prepares an image
cd ~/code/my-project
doz up              # a sandbox for this folder, its agent running, your terminal attached

Requirements

  • A Mac with Apple silicon and macOS 26 (Tahoe) or later.
  • Homebrew. Each release is also a tarball on the releases page.
  • For an agent: an account it can use, such as this Mac's own Claude Code or Codex login (read, never copied), an API key, or a Claude setup token.

Channels

dozStable. Recommended.
doz-betaBeta (and stable).
doz-canaryEvery build, first.

Install one with brew install dozer-sandbox/tap/<channel>; doz update --channel beta switches, and your sandboxes and settings stay. doz is signed and notarised. It tells you when a release is out, from an update feed signed with the project's own key, and never installs anything that does not verify. See Installing, upgrading and uninstalling.
